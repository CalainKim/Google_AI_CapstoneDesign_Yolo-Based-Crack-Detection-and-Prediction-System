## 1. 동작 시나리오 (Primary + 확장)

### 확정: Primary 시나리오 = 스마트폰 순회 자가점검

관리 담당자가 **스마트폰만 들고 순회**하며 균열 의심부를 촬영 → 앱이 즉석에서 안전등급(A~E) + 트리아지 판정 → **D·E만 전문 정밀안전진단으로 에스컬레이션**.

```
[월 1회 순회 점검]
 담당자가 시설 순회 → 균열 의심부 스마트폰 촬영
        │
        ▼
 앱: 결함 탐지 → 안전등급 A~E → 트리아지(정밀진단 필요 여부/긴급도)
        │
        ├─ A~C : 자가점검으로 관리 (이력 누적, 보수계획)
        └─ D·E : 정밀안전진단 우선대상으로 대시보드에 자동 등록
                    → 관리자가 예산 배정해 전문기관 의뢰
```

### 왜 드론·CCTV가 아니라 스마트폰인가 (스테이크홀더 규율)

우리 타깃은 **예산 부족한 관리 주체**. 시나리오는 타깃의 제약과 일치해야 한다.

| 후보 시나리오 | 장비/비용 | 우리 타깃에 맞나 | 결론 |
|--------------|----------|----------------|------|
| **스마트폰 순회** | 이미 보유, 0원 | 예산 없이 즉시 도입 가능. 법정 "육안점검"과 정합 | ✅ **Primary** |
| 드론 촬영 | 기체+조종+공역 = 고비용/전문 | 우리가 *차별화 대상으로 삼는 고비용군* 그 자체 | 확장(대형·접근불가 구조물), 후순위 |
| 공사장 CCTV 상시 | 카메라 인프라, 건설사 대상 | 스테이크홀더가 다름(건설 안전) = 다른 시장 | 확장2(별도 제품), 범위 밖 |

→ 드론/CCTV를 primary로 잡으면 "저비용"이라는 핵심 논리가 무너진다. **스마트폰 primary를 고정**하고, 드론·CCTV·엣지카메라는 "동일 트리아지 엔진 위에 얹는 확장 채널"로 로드맵에 둔다(엔진은 입력 소스에 독립적).

## 2. 스테이크홀더 정의 (누가 무엇을)

| 역할 | 실체 (예) | 하는 일 | 우리 제품과의 접점 |
|------|----------|---------|-------------------|
| **구매 결정자 (Buyer)** | 지자체 시설관리 부서장 / 관리사무소 운영주체 | 예산 승인, 도입 결정 | ROI(진단비 절감)로 설득 |
| **현장 사용자 (Field)** | 시설 담당 공무원 / 관리소 직원 | 순회하며 촬영 | **모바일 앱** |
| **관리자 (Admin)** | 같은 부서 관리자 | 여러 시설 등급 현황 파악, 정밀진단 예산 배분, 보고 | **웹 대시보드** ← 3번 질문의 답 |
| 외부 - 에스컬레이션 | 정밀안전진단 전문기관 | D·E 시설 정밀진단 수행 | 우리가 넘기는 대상(연계) |
| 외부 - 제도/감독 | 국토안전관리원, 지자체 | 제3종시설물·소규모취약시설 관리 감독 | 자문·실증·신뢰 앵커(§4) |
| 수혜자 | 시설 이용 주민 | (간접) 안전 | 명분 |

**대시보드 사용자 = 관리 주체의 관리자(지자체 부서/관리사무소).** 회사에 파는 경우엔 그 회사의 시설안전팀. 시민이 쓰는 것이 아님(그건 타 학생팀의 시민참여 모델 — 시장이 다름).

## 3. 제공 형태 · 사업성

### 제공 형태
- **모바일 앱**(현장 촬영·즉석 판정) + **웹 대시보드**(SaaS, 시설 포트폴리오 관리).
- 배포 옵션 2트랙:
  - **클라우드 SaaS** (일반) — 관리 편의, 빠른 도입.
  - **온프레미스/로컬** (보안 민감 공공) — 데이터 외부 유출 없음. §5 로컬 LLM과 연결.

### 과금 모델 (B2G / B2B 구독)
- 기본: **연 구독 (관리 시설 수 or 담당자 seat 기준)**.
- 예시 티어: 소규모(시설 N개) / 표준 / 온프레미스 라이선스.
- add-on: **자동 리포트 생성**(§5), 정밀진단 기관 매칭 연계.

### 사업성 논리 = 비용 (기술 자랑 아님)
- 정밀안전진단 1건 = 수백만 원대. 관리 시설이 수십~수백이면 전수 진단은 예산상 불가.
- 우리는 **진단 대상을 D·E로 선별** → *진단 예산을 실제 위험처에 집중*. 
- 셀링 문장: **"전수 정밀진단 대신, 우리가 골라준 위험 시설만 진단해 진단 예산 N% 절감."**
- 대시보드의 **선별 절감률**(방금 구현한 `triage.saving_rate`)이 이 주장의 실데이터 근거.

## 4. 컨택 (최우선 액션)

### 1순위: 학내 유사 분야 교수님
- 대상: 구조공학 / 토목 / 시설물 안전진단 / 콘크리트 재료 전공 교수.
- 요청: 트리아지 등급 기준·결함 심각도 가중치·실증 설계 **자문**, 가능하면 현장 사진 라벨/검증 연결.

### 2순위(여의치 않으면): 공공기관
- **국토안전관리원** — 시설물 안전 총괄, 제3종시설물·소규모취약시설 제도 주관. 자문/제도 정합성/실증 파트너로 최적.
- 지자체 시설관리공단, 한국건설기술연구원(KICT) — 데이터·현장 접근.

### 컨택 메일 초안 (복사해서 다듬어 사용)
> 제목: [OO대 캡스톤] 저비용 시설물 안전점검 선별(트리아지) 자문 요청
>
> 안녕하세요. OO대 OO학과 캡스톤 팀입니다.
> 저희는 예산이 부족한 소규모 노후 시설 관리 주체를 위해, 스마트폰 촬영만으로 균열·결함을 탐지해 국토부 안전등급(A~E)을 매기고 **정밀안전진단이 급한 D·E 시설을 선별**해 주는 저비용 도구를 개발 중입니다. 진단을 대체하지 않고 그 앞단에서 우선순위를 골라 진단 예산을 절감하는 것이 목표입니다.
> 등급 판정 기준의 타당성과 실증(정확도 검증) 설계에 대해 짧게 자문을 구하고 싶습니다. 15~20분 면담이 가능할지 여쭙습니다. 감사합니다.

→ **이번 주 발송이 최우선.** 응답 여부가 §7 실증(전문가 라벨) 확보를 좌우함.

## 5. 리포트 기능 — 로컬 LLM vs API 분기

점검 결과(시설명·등급·결함내역·권장조치·긴급도)를 **자연어 점검 리포트**로 자동 생성.

| 분기 조건 | 엔진 | 이유 |
|----------|------|------|
| **보안 민감 / 온프레미스 공공** | **로컬 Gemma** (예: Gemma 2 2B·9B, 엣지/온프레미스) | 데이터가 기관 밖으로 안 나감 |
| 일반 / 비민감 | **Gemini API** | 관리 부담 적고 품질·속도 우수 |

- 구현: `report_service`에 **provider 추상화**(`local | gemini`) — 설정 스위치 하나로 전환. 프롬프트·출력 스키마는 공통.
- 산출물: 등급 근거 요약 + 권장 조치 + (D·E면) 정밀진단 의뢰서 초안.
- 참고: 개발 환경은 Claude지만 **제품 LLM은 사용자 지정대로 Gemma/Gemini로 간다**(혼동 금지).

## 6. 기존 솔루션 비교 · 포지셔닝

### 비교 표

| 솔루션 | 비용 | 장비/전문성 | 대상 규모 | 상시성 | 관리주체가 스스로 쓰나 |
|--------|------|------------|----------|--------|----------------------|
| 정밀안전진단 전문기관 | 매우 높음 | 전문가 필수 | 중·대형 | 주기적(비쌈) | ✕ (외주) |
| 드론+AI 점검 서비스 | 중~높음 | 기체·조종 | 대형/접근난 | 이벤트성 | ✕ |
| IoT 센서 상시모니터링 | 설치비 높음 | 시공 필요 | 대형 핵심 | 상시 | 일부 |
| 시민참여 신고 앱(타 학생팀) | 낮음 | 불필요 | 산발적 | 비정기 | ✕ (시민 신고, 비관리) |
| **우리 (스마트폰 트리아지)** | **매우 낮음** | **불필요(폰만)** | **소규모 노후 다수** | **정기 순회** | **✓ 관리자가 직접** |

### 포지셔닝 맵 (빈 사분면 공략)
- X축: 도입·운영 비용(저→고), Y축: 접근성/자가운용성(낮→높).
- 우리는 **저비용 × 고자가운용** 사분면 — 경쟁군이 비어 있음. (정밀진단/드론/IoT는 고비용, 시민앱은 비관리.)

### "먼저 자료 넣을 필요 없다?" 에 대한 답
- **초기엔 정성 비교(위 표·맵)로 충분.** 정량 벤치마크(수치 대조)는 §7 실증 데이터가 나온 뒤 채운다. 지금 없는 숫자를 넣으면 검증 불가 클레임이 되어 피벗 취지(과대 클레임 제거)에 어긋남.

## 7. 정확도 평가지표 · 실증 (사용자 관점 최종 정확도)

두 층위를 분리한다.

### (A) 모델 지표 — 개발 단계
- mAP, 클래스별 precision/recall(균열·철근노출·박락 등), 균열 폭 오차(px→mm 환산).
- 데이터: 서울시 노후주택 데이터셋 구조물 3종 val set(§7.5 참조). 클래스 불균형은 focal loss/class weight로.

> **핵심(교수님이 원하는 실증):** 서울시 노후주택 데이터셋은 이미지별 **우수/보통/불량 등급 라벨**을 내장.
> 우리 A~E 출력 → 우수(A·B)/보통(C)/불량(D·E)에 매핑해 **등급 confusion matrix**를 바로 산출 가능.
> 즉 **전문가 라벨 확보(§4) 없이도 "사용자 체감 최종 등급 정확도"를 실증**할 수 있다(§4 지연 시에도 실증 진행).

### (B) 사용자 최종 정확도 — 실증 (교수님이 원하는 "실증 가능한 지표")
핵심은 **모델 정확도가 아니라 트리아지 결정의 정확도**:
- **선별 재현율 = 위험 누락률**: 우리가 A~C로 "괜찮다" 한 것 중 실제로는 정밀진단이 필요했던 비율. ← **안전상 가장 중요(놓치면 안 됨)**.
- **에스컬레이션 정밀도**: 우리가 D·E로 올린 것이 실제 정밀진단에서도 조치 대상이었나(헛경보율의 반대).
- **트레이드오프 KPI**: (위험 누락률 ↓) vs (선별 절감률 ↑)를 함께 보고. 안전 도구이므로 재현율 우선.

### 실증 방법 (실행 가능하게)
1. **데이터 등급 라벨로 1차 실증**: 노후주택 데이터셋 우수/보통/불량 vs 우리 A~E 등급 → confusion matrix. (전문가 라벨 불필요, 즉시 가능)
2. **스마트폰 현장 사진 소량 직접 촬영**(데이터는 일반/드론 촬영 → 스마트폰 도메인 갭 보정).
3. 필요 시 그 사진에 **전문가/정밀진단 실결과 라벨**을 더해 2차 실증(§4 자문 라인).
- "대규모 사전학습 → 소량 현장 파인튜닝(domain adaptation)" 자체가 방법론적 강점(P0에 포함).

## 7.5 데이터셋 전략 (gap1 해결)

**gap1(상가 데모 ↔ SOC-only 데이터) 해소됨** — 건축물 데이터셋 확보. 3종 역할 분담:

| 데이터셋 | 대상/촬영 | 등급라벨 | 역할 |
|---------|----------|---------|------|
| **A. 서울시 노후주택 (81만장)** | 건축물, 지상 근접, RGB+열화상 | **우수/보통/불량 ✓** | **P0 리드** — 상가/주택 데모 + 등급 실증 |
| B. 드론 건물/SOC (50만장, COCO) | 교량·댐·옹벽·건물, 드론 | 없음 | 물량·대형/SOC 확장, 사전학습(드론 도메인갭) |
| 기존 SOC 균열패턴(71769) | SOC, 스캐닝·드론 | 없음 | 소규모 SOC(옹벽·지하차도) 보조 |

**결정:**
- **리드 = A (노후주택).** 구조물 3종(균열·박리·철근노출)만 사용, 거주성 항목(대지/마감/생활/창호) 제외. 지상 근접이라 스마트폰 도메인에 가장 가깝고, 우수/보통/불량 라벨로 §7(A) 등급 실증이 즉시 가능.
- **열화상(A의 특징)** = 표면 RGB vs 내부 열화 → 향후 차별화 기능. MVP는 RGB만.
- **B(드론)** = COCO라 YOLO 변환 쉬움 + facility/위경도 있음. 물량 사전학습용, 단 드론 도메인갭 주의(스마트폰 파인튜닝 필요).
- **Colab Pro 주의**: 81만장 전량 학습 불가 → 구조물 3종 RGB **균형 subset**(등급·주택유형 고루) 후 학습.
